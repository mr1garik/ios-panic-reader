# Для разработчиков

[← назад к описанию](../README.md)

## Запуск из исходников

```bash
pip install -r requirements.txt
python ios_panic_reader.py
```

Отчёт в консоль без окна:

```bash
python ios_panic_reader.py --cli путь\к\логам
```

Новый релиз выходит сам: поменяйте номер в файле `VERSION` и текст в `RELEASE_NOTES.md` —
после сборки GitHub опубликует релиз с файлами для Windows и Mac.

Собрать локально: Windows — `build.bat`, Mac — `./build_mac.sh` (оба вызывают `python build.py`).
Каждая сборка на GitHub проверяет автообновление по-настоящему: собранная программа обновляет
сама себя до тестовой версии 9.9.9 на Windows и Mac, и проверяется, что данные пользователя целы. Запуск из исходников на Mac —
двойной клик по `start.command`. Тесты — `python -m unittest discover -s tests`.

## Языки

Русский, английский и украинский: переключатель RU / EN / UK вверху справа (язык меняется после
перезапуска). При первом запуске выбирается язык системы. Переводы интерфейса — `translations.json`,
переводы базы ошибок — поле `i18n` у записей в `errors_db.json`; тест `tests/test_i18n.py` не даст
оставить фразу без перевода.

## База ошибок

Вся база — один файл `errors_db.json`: паники, датчики (mic1, prs0, TG0B…), шины I2C по моделям,
коды iTunes/Finder (9, 4013, 53…), коды вылетов приложений (0x8badf00d…), симптомы, форматы логов.
У каждой записи — источники и надёжность: документация Apple, многократно подтверждено, или
«по сообщениям сервисов». Более новую базу можно положить в `Документы/iOSPanicReader/errors_db.json`
— программа возьмёт её, если версия базы не ниже встроенной.

## Свои ошибки

Скопируйте `user_kb.example.json` в `Документы/iOSPanicReader/user_kb.json` и добавьте записи
(там файл переживает обновления; старое место рядом с программой тоже работает).
`patterns` — текст или регулярные выражения, по которым ошибка находится в логе.

## Файлы

* `ios_panic_reader.py` — точка входа
* `gui.py` — окно программы
* `core.py` — разбор логов, вывод о проблемах, таблица деталей
* `device.py` — связь с iPhone (pymobiledevice3, работает на Windows и macOS)
* `errors_db.json` — база ошибок (один файл)
* `knowledge_base.py` — загрузка базы
* `history.py` — история телефонов и ремонтов
* `report_pdf.py` — PDF-отчёт для клиента
* `updater.py` — проверка, загрузка и установка обновлений
* `i18n.py`, `translations.json` — языки интерфейса
* `tools/screenshots.py` — скриншоты и GIF для README
* `assets/` — иконка программы (`icon.svg` — исходник, `.ico` для Windows, `.icns` для Mac)

## Ограничения

* Подсказки — ориентир для диагностики, а не окончательный диагноз: расположение датчиков
  зависит от модели.
* Автоматическая проверка оригинальности деталей пока не сделана — программа подсказывает,
  где это посмотреть на самом iPhone («История деталей и обслуживания»).

## Скриншоты для README

Скриншоты и GIF в `docs/screenshots/<язык>/` снимаются на демонстрационных данных:

```bash
Xvfb :99 -screen 0 1600x1000x24 &
DISPLAY=:99 python3 tools/screenshots.py          # ru, en, uk
```

## Как устроено автообновление

Программа сама проверяет новые версии (не чаще раза в 6 часов), скачивает их в фоне
и показывает плашку «Доступна версия …». Обновление ставится по кнопке «Перезапустить и
обновить» или при закрытии программы. Отключить — нажмите номер версии вверху справа.

Данные при обновлении не трогаются: всё лежит в `Документы/iOSPanicReader` (история, логи,
`user_kb.json`), заменяется только файл программы. Перед обновлением делается копия истории в
`backups/`, прошлая версия программы сохраняется в `previous/`.
